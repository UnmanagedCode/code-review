# Git plumbing gotchas

- **Everything runs through cc's `POST /api/exec`**, local checkouts included (`src/exec.js`): no `execFile`, no `fs` on a checkout. Always `cwd: "/"` (a vanished checkout is then git's own answer, never an ambiguous `EXEC_SPAWN_FAILED`), always argv form (no quoting, no login profile), always `encoding: "base64"` (the only way to get bytes back exactly; decoding the Buffer as UTF-8 reproduces what `execFile`'s utf8 and `readFileSync(…,'utf8')` gave, invalid bytes included). Paths travel as `sh -c SCRIPT sh <path> …` arguments, never interpolated.
- **`git diff <commit>` rewrites `.git/index`** (stat refresh) even with `GIT_OPTIONAL_LOCKS=0` or `--no-optional-locks`; `git status` and `ls-files` do not. Uncommitted diffs run with `GIT_INDEX_FILE` pointing at a private temp copy, made **on the target** (`<TMPDIR>/cr-index-<id>`) by the `SCAN` script (`src/git.js`), which also runs the tracked diff and the untracked listing; `FINISH` uses and then removes it. The script runs after `cd` into the checkout, so it checks the base (`TEMP_BASE`) **before** making the dir: a relative `TMPDIR` would otherwise land inside the checkout, and one inside the checkout or the common git dir would write the tree or `.git`; all are `TEMP_UNUSABLE`, as is a base with `\n`/`\r`. The JS-side check of the printed dir (`isTempDir`, plus the basename `cr-index-<id>`) is structural, not a regex: a `.` without the `s` flag misses line terminators. **The id is chosen in JS** (`randomBytes`), not by `mktemp`, so when a `SCAN`'s exec fails (timeout, unreachable) and nobody knows whether the dir exists, `REMOVE_BY_ID` removes it by id. In a linked worktree the index lives under the common git dir's `worktrees/<name>/`, so its path always comes from `rev-parse --git-path index`, never from `<checkout>/.git/index`. The copy takes the original's times exactly (`touch -r`): a copy that looks newer than its entries defeats git's racy-timestamp check, and a same-size edit made within one filesystem tick is then missed. (cc's exec has no utimes primitive, so `touch -r` inside the script is the way.) A missing index is not copied (git starts empty). `tests/snapshot.test.js` asserts byte-identical indexes for main and linked checkouts (and the copy's mtime, read by an `execHook` on `FINISH`), `tests/remote.test.js` the whole `.git` over exec, `tests/readOnly.test.js` the whole tree over every read route.
- **The read-only invariant is the easiest to break; guard it before touching `SCAN`/`FINISH`.** `tests/readOnly.test.js` (tree + `.git` + `TMPDIR`) and `tests/uncommittedGolden.test.js` (byte-identical `files`/`fingerprint`/lines) must stay green on every change to the snapshot path.
- **Script exit codes avoid sh's own.** dash exits 2 on a syntax or arithmetic error (e.g. `$(( ))` of an empty `wc` output), 126/127 on a command it cannot run, 128+ on a signal; so "path missing" is `PATH_MISSING` (10), and an exit 2 is a loud `Error`, never `CHECKOUT_GONE`.
- **`core.splitIndex=true`:** the private copy links to the real `sharedindex.<sha>`, so writing it would write a new shared index into the real git dir; every call passes `-c core.splitIndex=false` (git still reads the split index, and writes the copy whole). **Git itself still bumps the existing `sharedindex.*`'s mtime on every read of a split index** (freshen-on-read, as a plain `git status` does; no config disables it), so that one mtime is the only `.git` stat a read changes; the split-index byte-identity tests allow only that field.
- **The alternates entry is passed to `FINISH`** because its C-quoted form is built in JS (`cQuote`) from the objects path `SCAN` printed; it is written only when something is restaged, after the blobs. Teardown is `FINISH`'s `trap`; between `SCAN`'s exit (its trap is then disarmed) and `FINISH`, any failure removes the dir: by id while reading `SCAN`'s output, by path (`discardTemp` → `removeTemp`, which refuses any path whose basename is not `cr-index-*`) while planning or running `FINISH`; a failed removal is a warning naming the dir, not an error.
- **Diff flags are pinned** (`DIFF_FLAGS`): user config for external diff, textconv, prefixes or relative paths would otherwise change the parsed shape.
- **`git diff --no-index` exits 1 when files differ**; `FINISH` and `DIFF_UNTRACKED` (run by `diffUntrackedBatch`) treat 0 and 1 as success.
- **Paths can be C-quoted** (`"a\tb"`, octal-escaped UTF-8) in `diff --git`, `---`/`+++` and `rename` lines; `unquote` in `src/diff.js` decodes them. A binary file has no `---`/`+++`, so its path comes from the `diff --git` line.
- **A branch `base` is stored as given and re-resolved through `merge-base <base> HEAD` every round** (`...` semantics). After `sync_worktree` moves the base forward, the range still shows only the checkout's own work. A sha base stays fixed.
- **The empty tree** (root commits, unborn HEAD) comes from `hash-object -t tree --stdin`, so it is correct for the repo's hash format.
- **Refs are untrusted input:** `checkRef` rejects anything outside `REF_RE` or starting with `-`; resolution uses `--end-of-options`.
- **Worktrees share the object store**, so range/commit reviews of a deleted worktree stay readable via the main checkout; only a garbage-collected sha gives `SNAPSHOT_GONE`.
- **fsmonitor:** every git call passes `-c core.fsmonitor=false`; with `core.fsmonitor=true` a plain `git status` spawns a detached daemon and writes `.git/fsmonitor--daemon*`. `tests/snapshot.test.js` compares the `.git` tree before and after. Not neutralised: a clean/smudge filter named by the reviewed repo's `.gitattributes` (git-lfs) still runs on working-tree paths, since a correct diff needs it.
- **`git rm --cached` paths** are in HEAD, absent from the index and present on disk: `diff HEAD` says deleted and `ls-files --others` says untracked. `readUncommitted` (`src/snapshot.js`) stages those paths into the private index and re-diffs, so the path appears once. `update-index --add` writes the blob, so the private index comes with a private `GIT_OBJECT_DIRECTORY` (real objects named in its `info/alternates` file); otherwise a recoverable copy of content the user deliberately untracked lands in the real `.git/objects`. **Never use `GIT_ALTERNATE_OBJECT_DIRECTORIES` for that:** it is colon-separated, so a checkout path containing `:` is split into bogus entries and every uncommitted review there fails; the alternates file takes one path per line, but a newline in the path would split it and a leading `#` comments it out, so `cQuote` in `src/git.js` always writes the entry C-quoted (control, `"`, `\` and non-ASCII bytes escaped; git unquotes entries starting with `"`). Restaged paths obey the size cap and are staged one by one inside `FINISH` (the result a batch-then-per-path fallback gave), so an unreadable one (a required clean filter, no permission, a `core.safecrlf` refusal) becomes `tooLarge`; vanished ones stay deleted.
- **Writing an object git already has freshens it.** `update-index --add`, `hash-object -w` and every other object write bump the mtime of the existing loose object or pack when the blob is already there, alternates included: a read that restages an unchanged `rm --cached` path would touch `.git/objects`. So `FINISH` hashes with `-w` while the private object dir has **no** alternates (the blob is written privately, the real store never asked), writes the alternates file afterwards, and stages with `update-index --add --cacheinfo` (no object write). The mode is computed in the script as `update-index --add` would (`120000` symlink, `100755` owner-exec with `core.filemode`, else `100644`); `hash-object` without `-w` is not used because it skips `core.safecrlf`'s refusal. `tests/snapshot.test.js` compares the result with `git add`; `tests/readOnly.test.js` pins no freshen for a loose and a packed blob.
