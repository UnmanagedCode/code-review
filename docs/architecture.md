# Architecture

Backend internals. Behaviour: [features.md](features.md); wire formats: [protocol.md](protocol.md).

## Modules (`src/`)

Services return a plain object or a refusal `{ok:false, code, reason}`. Low-level helpers throw `Refusal`; `attempt()` converts it. REST routes and MCP tools call the same service functions; neither surface has logic of its own. `server.js` mounts `apiRouter()` under `/api`; its `start()` runs `migrateStore()` before it listens.

## Store

- Location: `<root>/reviews/<id>.json`, id `r-<10 hex>`; ids are validated before touching the filesystem. The root is outside every project tree, so it survives plugin updates.
- The `changes` emitter has no listener cap (one listener per open SSE client). Message bodies are capped at `MAX_BODY_CHARS`.
- `read(id)` throws `MisfiledReview` when the file's content has another `id` (or none): `write` persists under the content's id, so reading such a file as `id` would let any mutation copy it over another review, or create one. Nothing reads or writes through it.
- `list()` (the review list, `openReview`'s reuse check) skips and logs any file it cannot read, so one bad file hides only itself; opening that review by id still fails (500). Skip logs go through `logSkipped`: one line, the id cleaned and the error as `errorLine` (its name and message with whitespace collapsed and control characters removed; a parse error quotes the file's bytes). A route's unexpected error (500) logs the same single header line, `code-review: <METHOD> <url> failed: <Name>: <message>`, followed by the stack's frame lines only (`stackFrames`: the `    at …` lines after V8's `name: message` header, skipped by line count, so no message text follows the header).
- Writes are atomic (tmp file in the same dir, then `rename`); every write bumps `rev` and emits `change`. `mutate(id, fn)` runs under `withLock(id)` and writes only if `fn` changed the review; creation runs under `withLock('create')`.
- A review that cannot be read (unparsable JSON, `MisfiledReview`) is skipped and logged by `list()` (`code-review: review <id> skipped: <ErrorName>: <message>`) and still fails loudly when opened by id.
- Review fields: `id, project, worktree, branch, kind, target, baseLabel, title, status, createdAt, lastActivityAt, createdBy, recipient, author (session id; absent or `null` = none, so the recipient is the author), seenByHuman, rev, seq, humanSeq, agentSeq, nextThread, nextSubmission, rounds, verdicts, threads, droppedThreads, submissions`.
- `seq` is a review-wide counter bumped (`bump` in `reviews.js`) by every message, verdict and human status change, and by a refresh that adds a round. `humanSeq` is the `seq` of the last human one; `agentSeq` the `seq` of the last agent message or agent refresh that added a round (refreshes record no actor elsewhere). Unread counts, "since last delivery" and `turnOf` compare `seq`s.
- `lastActivityAt` (ISO) is stamped by `touch` (`reviews.js`): every `bump`, `composeSubmission` and `recordResult`; `openReview` sets it to `createdAt`. It is the one wall-clock value logic reads, and only to order the inbox across reviews; every other `at`/`createdAt` is display-only.
- Thread fields: `id, kind, severity, status, disposition, resolution:{by, seq}|null, resolveProposed, statusSeq, openedBy, anchor, pastAnchors, humanReadSeq, createdAt, messages`.
- A thread's `humanReadSeq` is the `seq` the human has read up to. A human status change takes its own `seq`; opening and agent resolves share the `seq` of their message (how the prompt tells them apart).

### Migrations

- `migrateStore()` (`src/migrate.js`) runs once per start, in `server.js` `start()` before `listen`. It lists `store.ids()` and runs each review through `store.mutate`, so a review it leaves unchanged is not rewritten.
- Each step self-checks: it fills only fields that are missing, so a second run, or a review already in the current shape, writes nothing.
- Any per-review failure (a file `mutate` cannot read, a write error) is logged (`logSkipped`, `not migrated`) and skipped; an unreadable file stays byte-identical. Only a failure to list the store (`store.ids()`) stops the start, and an unconfigured store (`STORE_UNCONFIGURED`) is a no-op.
- So an open review can still lack the current fields (a skipped file, or one copied into `reviews/` while the server runs). `listInbox` guards against it: such a review is logged (`logSkipped`, `left out of the inbox`) and dropped from the inbox, with no fallback value; every other row still shows.
- Current steps: `lastActivityAt` = the latest of `createdAt`, message `at`s, verdict `at`s, round `createdAt`s, submission `composedAt`s and `deliveredAt`s; `agentSeq` = the highest `seq` of a non-human message, else 0. Rounds carry no actor, so agent refreshes stored before `agentSeq` existed are not counted.
- Application code reads the current shape only; a new format change adds a step here.

## Places and host exec

- **Place:** `{system, remoteId, path}`, the one value that addresses a checkout wherever a path used to be passed to git. `lookupCheckout` builds it from cc's location row (`GET /api/projects/:name/location`; a worktree takes its project's `system` and `remoteId`) and returns `place` and `mainPlace` beside `path`/`mainPath` (those stay for messages and the picker), running nothing. `placeKey(place)` keys caches: one path can exist on two systems.
- **Every checkout, local ones included, is read through `POST /api/exec`.** No module in `src/` spawns a process, and only `store.js` (code-review's own store) and `opsLog.js` (the operator log) touch the filesystem; `tests/exec.test.js` guards both.
- **Request shape** (`exec` in `src/exec.js`): always form B with `cwd: "/"` (a vanished checkout is then git's or the script's answer, never an ambiguous spawn failure), always `argv` (no quoting, no login profile), always `encoding: "base64"` (decoded to Buffers; callers wanting text decode UTF-8 exactly as `execFile`/`readFileSync` did, so invalid UTF-8 comes out the same). `stdin` is sent as `stdinB64`; absent = closed stdin. `maxOutputBytes` is clamped to `EXEC_MAX_OUTPUT_BYTES`. The fetch deadline is `timeoutMs + min(10 s, timeoutMs)`, so cc reports `EXEC_TIMEOUT` first; aborting the fetch kills the command. `readOnly` (default false) asserts the command writes nothing and is the only thing that allows a retry; in `src/git.js` the `read`/`readSh` wrappers set it, `run`/`sh` never do, so a new call site is not retried until it opts in. `PROBE` is read-only; `SCAN`, `FINISH` and the removals are writes (they make, fill or remove the private dir) and never retry.
- **Refusal mapping:** the table in [protocol.md](protocol.md#cc-routes-consumed). `UNREACHABLE` (`src/exec.js`) is the single list the degradation paths read (`UNREADABLE` in `src/reviews.js` and `src/context.js`).
- **Existence:** committed reviews and `/checkout` ask `PROBE` (one exec per request, memoised by `makeEnv`: which of the checkout and its main one exists, the current round's first missing sha, and the checkout's status when the first caller asks); uncommitted snapshots ask `SCAN` (exit `PATH_MISSING` → `CHECKOUT_GONE`); `openReview` and `/checkout/commits` still use `git.exists` (`[ -e "$1" ]`, symlinks followed). A system that cannot answer refuses (`SYSTEM_UNREACHABLE`); it is never read as missing. A path git finds missing evicts the project's cached lookups (`scope.evict`).
- **Degradation when a system is down:** `summaryOf` turns an `UNREACHABLE` refusal from the probe or snapshot (and `TEMP_UNUSABLE` from the snapshot) into `snapshotError` with `checkoutGone: false`, `dirty: false`, so the review list still lists every review; the uncommitted sweep skips (threads untouched). A committed review whose snapshot this process has cached needs only `PROBE`, so it stays readable while only the diff commands fail. Open, refresh, the picker, `diff`, `fileLines` surface the refusal itself (502/504).

### Scripts (`src/git.js`)

Scripts run as `['sh', '-c', SCRIPT, 'sh', place.path, …args]` with `cwd: "/"` and the `BASE_ENV` overlay, their first line the `unset` of `GIT_LOCATION_VARS` (see [Git](#git)), and call git with the same `BASE_ARGS` as argv calls (`${GIT}`). Flags embedded in a script are single-quoted (`shq`). Their exit codes avoid sh's own (1, 2 on a syntax or arithmetic error, 126/127, 128+): "the path is missing" is `PATH_MISSING` (10), so a broken script is never read as a missing checkout; "succeeded, but the trap could not remove the private dir" is `DIR_LEFT` (11, `FINISH` only). A trap that cannot remove its dir prints `LEFT_MARK` on stderr and, after a failure, keeps the failure's exit code.

| Constant | Does | Output |
|---|---|---|
| `PROBE` | read-only. Enters `$1` (the checkout) if it exists, else `$2` (the main checkout; `''` for uncommitted reviews and `/checkout`), else exits `PATH_MISSING`; `cat-file -e "$s^{tree}"` per sha; with `$3 = 1` and in the checkout, `git status --porcelain=v2 -z --branch --no-ahead-behind` (parsed by `parseStatus`, shared with `statusOf`) | `<checkout\|main>\0<first missing sha or empty>\0[status records]` → `{where, missing, status}` (`where: null` on `PATH_MISSING`) |
| `SCAN` | first uncommitted call. `PATH_MISSING` when the checkout is gone; `TEMP_BASE` (the `TMPDIR` checks: absolute, no `\n`/`\r` before and after `pwd -P`, outside the checkout and its common git dir, else exit 7); HEAD or the empty tree; `mkdir -m 700 <base>/cr-index-<id>` (id: 24 hex chosen in JS; failure exit 5), a `trap` removing it on any failure; `objects/info`, the index copied with `cp` + `touch -r` (exit 6); the tracked diff on that copy (`GIT_INDEX_FILE` only) and `ls-files --others --exclude-standard -z`; each over the limit, or both over the output cap, exit 9 | `<dir>\0<objects>\0<head>\0<tracked bytes>\0<others bytes>\0`, then both, sliced by byte length (`call(…, {bytes: true})`). JS checks the dir structurally (`isTempDir`) and that its basename is `cr-index-<id>` |
| `FINISH` | second and last call; its `trap` removes the dir however it ends. Restages each `rm --cached` path one by one: first its blob, `hash-object -w` (a symlink: its target, unfiltered; a file: through its filters) with `GIT_OBJECT_DIRECTORY` = the private dir while that dir has **no** alternates yet, so the blob is written there and the real store is never asked; then, with `info/alternates` naming the real objects dir (C-quoted), `update-index --add --cacheinfo <mode> <sha> <path>` (mode `120000` for a symlink, `100755` when the owner execute bit is set and `core.filemode` holds, else `100644`: what `update-index --add` records for a path the index lacks); then redoes the tracked diff if any staged; diffs untracked paths (`--no-index`) until their summed size passes a third of the limit, deferring that one and every later one; reads the prefetched lines (`n<path>`: `realpath` under `pwd -P`, a regular file; `o<path>`: `cat-file blob <head>:<path>` when it is a blob). Exit 9 when the redone diff or the untracked diff passes `maxDiffBytes`, or the output its cap; exit 6 for an unwritable dir | `<meta>\0<tracked>\0<untracked>\0<prefetch>\0` byte lengths, then the four parts; one meta line per argument (restage `-`/`O`/`F`/`S`, untracked `-`/`<size>`/`<size> D`/`<size> d`, prefetch `-`/`L`/`<bytes>`) |
| `REMOVE_BY_ID` | `rm -rf <resolved TMPDIR>/cr-index-<id>`: after a `SCAN` whose exec failed (timeout, unreachable, too much output, an unknown exit), when whether the dir exists is unknown | — |
| `OBJECTS_EXIST` | `cat-file -e "$s^{tree}"` per sha (past rounds; the current round's shas go through `PROBE`) | the first missing sha, else nothing |
| `OLD_LINE_COUNTS` | read-only; `diff --numstat -z --no-renames` from the empty tree to `<sha>` for the given paths, with `GIT_LITERAL_PATHSPECS=1` | `<lines>\t<n>\t<path>\0` per path present (`-` for binary) |
| `SIZES` | `ls -ldn` per path (lstat semantics: a symlink reports its own size) | one line per argument: the size, or `-` when absent; names are never echoed |
| `DIFF_UNTRACKED` | `diff <DIFF_FLAGS> --no-index -- /dev/null "$f"` per path; exit ≤ 1 is success | the concatenated diffs |
| `READ_FILE` | `realpath` (sentinel idiom, so a trailing newline in a name survives) must sit under `pwd -P` and be a regular file, then `cat` | the bytes; exit 3 → `null`; 126/127 (a missing tool) throws |

Exit mapping of the two snapshot calls: `SCAN` `PATH_MISSING` → `CHECKOUT_GONE` (and the project's lookups are evicted); 5, 6, 7 → `TEMP_UNUSABLE`; 9 → `DIFF_TOO_LARGE`; 3, 4, 8 and anything else → a plain `Error` with stderr. `FINISH` 6 → `TEMP_UNUSABLE`, 9 → `DIFF_TOO_LARGE`, `DIR_LEFT` → the result is answered and the left dir warned, others → `Error`. A failed `SCAN` whose stderr carries `LEFT_MARK` warns naming `cr-index-<id>`. Once `SCAN` exits 0 its trap is disarmed and the dir is code-review's until `FINISH`'s trap removes it, so every failure in between removes it: reading `SCAN`'s output (`REMOVE_BY_ID`, in `scanWorktree`), and planning the finishing call or `FINISH` itself (`discardTemp`, in `uncommittedDiff`; best effort, a `console.warn` naming the dir when it fails).

Plain argv calls: every other git command (`run`: `git <BASE_ARGS> -C <path> …`), `exists`, and the teardown `rm -rf -- <dir>` (`removeTemp`, which refuses any path whose basename is not `cr-index-*`).

### Exec calls per operation

Counted by the fake cc (`execCalls`; pinned in `tests/latency.test.js` and `tests/diffMeta.test.js`); locally each costs roughly an HTTP round trip plus JSON/base64, remotely the provider's latency on top. `harness/bench/requests.mjs` measures per-request round trips and wall time, `harness/bench/open-review.mjs` `openReview`.

| Operation | Exec calls |
|---|---|
| summary or detail of a committed review | 1 (`PROBE`) with its snapshot cached in this process; 2 cold (plus the diff) |
| summary or detail of an uncommitted review | 2 (`SCAN`, `FINISH`; the sweep's thread lines come back in `FINISH`); more only past `ARGV_BUDGET` of untracked path bytes or the untracked budget (`SIZES` for the overflow, then `DIFF_UNTRACKED` per chunk of at most `UNTRACKED_CHUNK` paths and a third of the limit) |
| `diff` | as the summary, plus at most 1 `OLD_LINE_COUNTS` the first time a file is shown at a base (cached by base sha and path, `LINE_COUNTS_MAX` entries) |
| a reply or thread status change | 0 on a committed review whose round this process has read; uncommitted: the sweep's 2 |
| picker `checkoutInfo` | 1 (`PROBE`) |
| `GET /inbox` | 0. It reads every stored review file (closed ones too: the status is inside) and makes at most P + W cc GETs: the location of each of the P projects with an open review, and the worktree list of each of the W projects with an open worktree review, `ROW_CONCURRENCY` at a time, none when nothing is open (fewer within the lookup TTL). A hanging cc delays it by the GET budget (`CODE_REVIEW_CC_TIMEOUT_MS`, with one retry); the rows then carry `checkoutGone: null` |

## Lookups and concurrency

- **Every checkout lookup reads cc's location route** (`cc.location`), never `GET /api/projects`, which fans out git work per project in cc; only the picker's own `GET /projects` lists projects.
- **`lookupScope()`** (`src/lookups.js`) is created once per request (route handler, `openReview`, `listReviews`, `checkoutInfo`, the inbox) and handed down through `viewReview`/`inReview`/`makeEnv`, `lookupCheckout`, `forkPoints`: each key (`l:<project>`, `w:<project>`, `list`) is fetched at most once per scope.
- **Cross-request cache:** keyed the same, `{at, promise}`, single-flight (concurrent callers share the in-flight promise), aged on the monotonic clock (`performance.now()`), so a wall-clock jump cannot revive an answer. Reused for `CODE_REVIEW_LOOKUP_TTL_MS` (default `DEFAULT_LOOKUP_TTL_MS`). Only positive answers are kept: a rejected lookup and a `null` location are dropped, so a new project resolves at once.
- **Invalidation:** a worktree missing from cached rows is re-asked once, bypassing the cache (`reask`), before `CHECKOUT_UNKNOWN`, so a new worktree resolves at once; when `PROBE` or `SCAN` finds the checkout path missing, `scope.evict(project)` drops `l:` and `w:`. Stale for up to the TTL, and why that is safe: a deleted project or worktree (git then reports the path missing: `checkoutGone`, `CHECKOUT_GONE`; only the inbox, which runs no git, shows `checkoutGone: false` meanwhile), a project moved to another system (the exec fails or finds nothing, which evicts), and a worktree's `branch`/`baseSha`/`baseWorktree` after a sync (picker and fork-point display only).
- **Concurrency:** `listReviews` resolves rows through `mapLimit(…, ROW_CONCURRENCY, …)` on one scope; the inbox resolves its lookups the same way. Rows keep their order. The cap is per request; each docker system already funnels execs through one provider process in cc.

## Git

- **The target's environment cannot move git or make it write:** cc merges the target's own environment under the `BASE_ENV` overlay, so a `GIT_DIR`, `GIT_INDEX_FILE`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`… set there would point a read at another repo, or let a private-index write find (and freshen) the real store, and a `GIT_TRACE*`/`GIT_TRACE2*` target would make a read write its trace file (into the tree, if it points there). `call` (`src/git.js`) therefore starts every command by unsetting `GIT_LOCATION_VARS` (git's `rev-parse --local-env-vars`, plus `GIT_NAMESPACE`) and `GIT_TRACE_VARS` (git's documented trace family): scripts get the `unset` as their first line, argv git calls run as `sh -c 'unset …; command -v git … || exit 12; exec "$@"' sh git …`. Every command that runs git (the wrapped argv calls and each script using `${GIT}`) first checks that git can be found and exits `GIT_MISSING` (12) when not, which `call` maps to `GIT_UNAVAILABLE`, the degradation cc's `EXEC_SPAWN_FAILED` gives when git is the command itself; a script's other missing tools (126/127) stay loud errors. They are unset, not overlaid empty: an empty `GIT_DIR`, `GIT_WORK_TREE`, `GIT_OBJECT_DIRECTORY` or `GIT_COMMON_DIR` breaks git, and an empty `GIT_REPLACE_REF_BASE` changes what it reads. The `rm` teardown runs no git and is not wrapped.
- Every git call: `git -c core.fsmonitor=false -c core.splitIndex=false -C <path>` (`BASE_ARGS`) with the `BASE_ENV` overlay (`LC_ALL=C`, `GIT_OPTIONAL_LOCKS=0`) on the target's own environment, on scripts too; diff flags are pinned (`DIFF_FLAGS` in `git.js`) so user config cannot change the parsed shape. `statusOf` and `PROBE` read head, branch and dirty state from one `git status --porcelain=v2 -z --branch --no-ahead-behind`.
- `git diff <commit>` rewrites `.git/index` even with `GIT_OPTIONAL_LOCKS=0`. Uncommitted diffs therefore run against a private copy of the index, made **on the checkout's system** by `SCAN` and used by both calls through `GIT_INDEX_FILE` set inside the scripts. The copy carries the original's exact times (`touch -r`), so git's racy-clean decisions on it are the original's own. A missing index is not copied. Restaging (`FINISH`) also sets `GIT_OBJECT_DIRECTORY` to the private dir. Its blobs are written (`hash-object -w`) before that dir has an `info/alternates` file, so they land there even when the real store already has them: git **freshens** (bumps the mtime of) an existing loose object or pack whenever it is asked to write an object it finds, alternates included, so staging with the real store reachable would touch `.git/objects`. Only then is the alternates file written (it names the real objects dir, so HEAD's objects resolve) and the paths staged with `--cacheinfo`, which writes no object. The entry is C-quoted (git unquotes entries that start with `"`; control, `"`, `\` and non-ASCII bytes are escaped), so a newline, quote, backslash or leading `#` in the path cannot split or comment it out. The alternates file is used instead of `GIT_ALTERNATE_OBJECT_DIRECTORIES` because that variable is colon-separated and would split a checkout path containing `:`. The dir's id is chosen in JS, so a `SCAN` that died mid-way can be removed by id (`REMOVE_BY_ID`). A dir that cannot be removed is a `console.warn` naming it (it sits in the target's tmp, never in the tree): a trap that fails says so (`DIR_LEFT`, `LEFT_MARK`), and JS's own removals warn when they fail. Git never writes the project's `.git` (index, objects, fsmonitor files); the only writes in a checkout are the reviewed repo's own filter drivers, if any (below). `tests/readOnly.test.js` pins this for every read route.
- Temp files code-review causes on a target: `<TMPDIR>/cr-index-<id>` only (its own, removed by `FINISH`'s trap, or by JS after a failure; a relative, missing, line-terminator-bearing, or in-checkout/in-git-dir `TMPDIR` is refused `TEMP_UNUSABLE` before anything is created). Never under the checkout.
- `core.fsmonitor=false` is passed on every call: with `core.fsmonitor=true` even `git status` starts a detached `fsmonitor--daemon` that creates `.git/fsmonitor--daemon*`.
- `core.splitIndex=false` is passed on every call: with `core.splitIndex=true`, writing the private index (restaging, a diff's stat refresh) writes a new `sharedindex.<sha>` into the real git dir, because the copy links to the real shared index. Off, git still reads an existing split index and writes the private copy whole.
- **Git's own freshen-on-read (split index):** every git command that reads a split index bumps the mtime of the existing `sharedindex.<sha>` it links to, content unchanged; a plain `git status` in the repo does the same, and no config disables it (it keeps shared indexes from `splitIndex.sharedIndexExpire`). That mtime is the one stat a code-review read can change in `.git`: no shared index is created, removed or rewritten, and nothing else changes. The split-index variants of the byte-identity tests in `tests/remote.test.js` allow exactly that field.
- **Known limitation:** a clean/smudge filter driver named by the reviewed repo's own `.gitattributes` (e.g. git-lfs) still runs on working-tree paths, because a correct diff needs it.
- Uncommitted snapshots hold one entry per path. A path HEAD has but the index lacks (`git rm --cached`) is staged into the private index first, so it shows as working tree vs HEAD (nothing if unchanged) instead of deleted plus added. Restaged paths obey `MAX_FILE_BYTES` like untracked ones (over the cap: a `tooLarge` `modified` entry with a file-level hunk); a path that vanished before staging stays deleted. `FINISH` stages them one by one, so a path git cannot read (e.g. a required clean filter exits non-zero, or `core.safecrlf` refuses it) becomes a `tooLarge` entry instead of failing the snapshot.
- Refs (`base`, `sha`) must match `REF_RE` and not start with `-` (`BAD_REF`), then resolve via `rev-parse --verify --end-of-options` (`REF_UNKNOWN`).
- Targets resolve to two shas per round: range → `merge-base <base> HEAD` and HEAD; commit → first parent (or the empty tree) and the commit; uncommitted → HEAD (or the empty tree on an unborn branch) for both, read by `SCAN` (so `buildSnapshot` returns them), new side read live. The empty tree comes from `hash-object -t tree --stdin`.
- Untracked files: `ls-files --others --exclude-standard -z` (in `SCAN`); only the first `MAX_UNTRACKED_FILES` are measured, the rest are `tooLarge` regardless. Up to `ARGV_BUDGET` of path bytes go to `FINISH`; the rest are measured by `SIZES` and joined to `FINISH`'s deferred ones, which `diffUntrackedBatch` diffs in order. `MAX_DIFF_BYTES` is the buffer limit (`DIFF_TOO_LARGE`) of every diff, checked per diff inside the scripts.
- Committed snapshots are cached in memory by `(placeKey(repo), baseSha, headSha, kind)` with each file's content hash; uncommitted ones are always live. The current round's shas are checked by `PROBE` (then `buildSnapshot({verified: true})` skips the check), a past round's in one `OBJECTS_EXIST` call.
- Repo used: the checkout when it exists; otherwise, for range/commit reviews, the project's main checkout (worktrees share the object store). A pinned sha missing from the store is `SNAPSHOT_GONE`.
- Working-tree reads (`readWorktreeFile`, the uncommitted new side, `FINISH`'s `n` prefetch) are contained: `realpath(file)` must sit under the checkout's `pwd -P` and be a regular file. A file over `MAX_DIFF_BYTES` is `DIFF_TOO_LARGE`. Prefetched content over `MAX_FILE_BYTES`, or past the budget, is read lazily instead (`L`), so a read error stays loud.

## lineCount and sig

- `lineCount` (`snap.lineCounts`): `added` → `{old: null, new: additions}`, `deleted` → `{old: deletions, new: null}`, binary/`tooLarge` → both null; modified and renamed: `old` = the count of `oldPath ?? path` at the snapshot's base (`OLD_LINE_COUNTS`, cached by `${baseSha}\0${path}`: content-addressed, so valid across places), `new = old + additions − deletions` (every old line is kept or deleted, and a "No newline" marker counts no line, as `splitLines` counts).
- `contentHash(path)`: `sha256(baseSha \0 headSha \0 JSON(file entry))`, built beside `files` (never inside, so `fingerprint`, which is stored in `rounds[]` and compared by uncommitted refresh, is unchanged).
- `sig` = `fileSig(contentHash, FileState, hunk verdicts, threads)` (`src/rollup.js`), each as the view renders it, from the same helpers that build the response (`liveView`, the past-round view with `roundThreadsOn`, compare's placed copies, `[]` for the commit filter), so equal sigs mean an identical file response by construction. CPU only.
- `fileSig` on writes: annotate and verdicts use the snapshot they already built; reply and status use the sweep's (uncommitted) or `env.cachedSnapshot()` (committed: no exec), else read it; any failure gives `sig: null` and never fails the write.

## Hunk ids and anchors

- Hunk id: `sha256(path \0 changedLines \0 occurrence)`, first 12 hex; `changedLines` is the `+`/`-` lines with prefixes, `occurrence` the index among identical blocks in the file. Line numbers and context are excluded.
- File-level hunk id: hash of path, status, oldPath, blob ids and modes.
- `linesHash`: sha256 (first 16 hex) of the lines with trailing `[ \t\r]` stripped, indentation kept.
- Anchor: `round` (the snapshot its `lines`/`linesHash` were read from; `followThreads` sets it to the new round on every re-anchor), selected `lines`, `ctxBefore`/`ctxAfter` (hash and count of up to `CONTEXT_LINES` neighbours), `hunkId` from `hunkFor` (the hunk containing `endLine`, else the last one overlapped, else null), `drifted`.
- `pastAnchors`: on range reviews, the thread's anchor in each round before `anchor.round` that it was re-anchored out of, oldest first, positional fields only (`anchorView`). `followThreads` appends the old anchor on every range refresh that relocates the thread. Uncommitted reviews never append (they have no past-round views); their threads keep `[]`. Outdated threads are never followed, so their last chain entry is the last round they were located in.
- Derived, not stored: a thread's creation round (`messages[0].round`); the round it went outdated (its last chain entry's round + 1); its status just before (`resolution` set → `resolved`, else `open`: going outdated changes only `status`).
- Not derivable: open/resolved as of an earlier round. Only the latest status change is stored (`statusSeq`, `resolution`), and rounds carry no `seq`, so past-round views show the current status (see the [protocol](protocol.md#shapes)).
- `locate(anchor, lines, mode)`: windows whose `linesHash` matches, ranked by context matches, then distance to the old start, then earliest. An exact match always reports `drifted: false`. Mode `reanchor` additionally accepts a unique `ctxBefore` followed by a unique `ctxAfter` with a gap of 1 to `2·len + 10` lines (`drifted`); mode `volatile` never does.

## Refresh and the uncommitted sweep

- Range refresh (under the review lock): re-resolve target; unchanged shas → no new round. Else build the new snapshot, keep verdicts whose hunk id survives, run `followThreads(…, 'reanchor')` with a rename map from `git diff -M --name-status <prevHead> <newHead>`, push the round.
- Uncommitted: `inReview` runs `followThreads(…, 'volatile')` before every read or write; unlocatable threads are deleted and remembered in `droppedThreads` (→ `THREAD_DROPPED`). The sweep is skipped when the checkout is unreadable. Refresh adds a round only when the snapshot `fingerprint` changed.

### Client data layer

- **One event stream per page load.** `lib/sse.ts` opens `api/events` on the first `subscribe`/`onReconnect` and never closes it when handlers unsubscribe (`resetSse()` is the test seam). `openSource` (`lib/sseSource.ts`) owns the EventSource: a transient `error` is the browser's to retry and the next `open` calls the reconnect handlers; an `error` that leaves `readyState` CLOSED (non-2xx, e.g. 503 `STORE_UNCONFIGURED` or a 502 while the plugin backend restarts) is reopened after `RETRY_MS`, doubling to `RETRY_MAX_MS`, and that `open` also counts as a reconnect.
- **Cross-tab stream** (SharedWorker). `lib/sseTransport.ts` picks, once on the first subscribe, a `SharedWorker` (`new URL('./sseWorker.ts', import.meta.url)`, module, name `code-review-events`) when `typeof SharedWorker === 'function'`, else `openSource` in the tab; one `api/events` connection per browser instead of per tab (the browser allows about six per origin, shared by every cc tab). The hub (`lib/sseHub.ts`, `createHub`) holds the one `openSource` for all connected ports.
  - **Messages:** tab → worker `{t:'hello', url}` and `{t:'bye'}`; worker → tab `{t:'review', data}` (raw event data, parsed in `lib/sse.ts`) and `{t:'reconnect'}` (to every port; each tab marks its entries stale and hidden tabs defer the refetch).
  - **URL:** the tab sends `new URL('api/events', document.baseURI).href`; the worker's own base is `assets/`.
  - **Lifetime:** the first `hello` opens the stream, the last `bye` (sent on `pagehide`) closes it; a persisted `pageshow` says `hello` again. A crashed tab sends no `bye`, but the browser ends the worker when no document owns it.
  - **bfcache:** a persisted `pageshow` re-sends `hello` and, in both transports, reports a reconnect, so entries stale and the mounted ones refetch. The listeners are removed when the transport closes.
  - **Fallback:** a worker `error` before its first relayed message (CSP, load failure) logs a warning and opens the tab's own stream.
  - **Seams:** `setTransportFactory` (reset by `resetSse`).
- **Resource cache** (`state/resource.ts`, in-house, no dependency). `useResource(key, {fetch, matches?, maxAgeMs?}, {keepPrevious?})` returns `Fetched` plus `loadedAt` and `placeholder`. One entry per key, shared by every hook with it; `version` is the entry's count of successful loads, global per key and surviving remounts.
  - **Mount:** no data → fetch; data → render it at once and revalidate in the background only if stale or older than `maxAgeMs` (default `MAX_AGE_MS`). Age is checked only on mount. An error keeps the previous data.
  - **Dedupe and races:** one in-flight fetch per key. An invalidation (`matches`, `reload()`, an aged mount) sets `staleGen`; a fetch that started before it cannot clear `stale`, and runs again when it ends.
  - **SSE:** one module-level `subscribe` and one `onReconnect`, made on the first entry with `matches` or `gone`. A matching event marks the entry stale; a mounted entry in a visible tab refetches after `DEBOUNCE_MS`. A reconnect stales every entry with `matches` and refetches the mounted ones at once.
  - **Hidden tabs:** nothing refetches while `document.visibilityState` is hidden; one `visibilitychange` listener refetches mounted stale entries when the tab shows.
  - **Eviction:** unmounted entries sit in an LRU of `MAX_IDLE_ENTRIES` (an entry joins it when its last hook unmounts, or at once when only `ensure` created it). The `loads` of an evicted entry are remembered (`lastLoads`), so a recreated entry's `version` keeps rising.
  - **Gone:** `spec.gone(event, data)` (the review: a `deleted` event) drops the entry's data and sets `gone`; a gone entry is never fetched, so a later mount reports `gone` from the cache (`useReview().deleted`).
  - **Join reloads:** `reload({ join: true })` (the poll's kick) does nothing while a fetch that started after the last invalidation runs, so a visibility flush or an aged mount and the poll are one request. A plain `reload()` always invalidates.
  - **`tag`:** `spec.tag()` is read when a fetch starts and returned as `dataTag` with the data it produced.
  - **Writes:** `mutate`/`mutateResource` patch the entry for every mount, without counting as a load. `ensure(key, spec, isCurrent?)` reads an entry without a component.
- **Keys** (`resourceKey`: parts NUL-joined, null/undefined as `''`):

| Hook | Key | Invalidated by events |
|---|---|---|
| `useProjects` | `projects` | no |
| `useCheckout` | `checkout\0project\0worktree` | no |
| `useSessions` | `sessions\0project\0worktree` | no |
| `useSessionPlaces` | `places\0sessionId` | no |
| `useReviewList` | `reviews\0project\0scope\0status` (`scope` is `*` for every checkout, `=<worktree>` otherwise) | every event except one at or below the shown row's `rev` |
| `useInbox` | `inbox` | every event |
| `useFileDiff` / `useThreadIndex` | `diff\0id\0round\0path` (`diffKey`; never aged) | no: sig-gated |
| `useReview` | `review\0id` | `rev` above the cached `review.rev` (a `deleted` event sets the entry `gone`) |

  Projects, checkout, sessions, places, the list and the inbox carry live fields no event announces, so they revalidate on a mount older than `MAX_AGE_MS`. `useFollowSession` refetches the project list when a session change names a project the list lacks and the list is older than `PROJECTS_RECHECK_MS`.
- **Sig gate** (`useFileDiff`, `state/diffResource.ts`). `FileState.sig` and `DiffFile.sig` are opaque; equal means an identical diff response. The open file's `diff` entry is refetched only when its cached `DiffFile.sig` differs from the `sig` of the open path in the current view's file list (review detail; the round view's files for a past round), compared once per (file, view sig), so a local `patchSig` does not read as stale. It compares the response's sig, not the sig the request was made under, so a diff fetched after a change matches the later review load. Without a `sig` on either side it falls back to refetching when the review's `version` moves past the `dataTag` the diff entry was fetched at (the review version then; a missing tag reloads; a diff fetched before the review ever loaded counts as version 1). `useThreadIndex` keys its effect on `path + sig` (`v<version>` as fallback) and reads each file with `ensure`, so only files whose sig moved are fetched and the open file is never fetched twice.
- **Own writes.** `useReviewActions` patches the cached diff locally, then reloads the review. A write response's `fileSig` `{path, sig|null}` sets the open file's cached sig (`patchSig`; ignored for another path or `null`), so the reload finds it current. Without it, one diff refetch per write remains.
- **Line counts.** `DiffFile.lineCount {old, new}` (null for a missing side, binary or too-large) gives `total` for the displayed side outside comparisons; a comparison reads a round's head, so it and responses without `lineCount` use `fileLines(…, 1, 1)`.
- **Switching files.** `useResource(…, {keepPrevious})`: on a switch to an uncached file `file` stays the previous one with `switching` true and `loading` true; `expand`, `reveal` and context reads do nothing meanwhile. `FileDiff` marks its root `aria-busy`, `inert` and dimmed; `Loading` shows only on a cold first load.
- **Polling** (`usePolling(reload, enabled, loadedAt)`, uncommitted reviews only). While visible, a timer fires `POLL_MS` after the later of the last load and the last kick; hidden pages clear it. `focus` and `visibilitychange` share one gate: no kick within `REFOCUS_MIN_MS` of the last kick or load, so returning to a tab sends one request and clicking into the iframe at most one per `REFOCUS_MIN_MS`.
- **Test seams:** `resetResources()` and `resetSse()` (both called by `test/setup.ts`), `setEventSourceFactory`, `setTransportFactory`. happy-dom has no `SharedWorker`, so tests stub the global to exercise the worker path.


### UI tests

`npm run test:ui` (vitest, happy-dom). `src/test/` holds the shared fakes:

- `setup.ts`: cleanup, `vi.unstubAllGlobals()`, deletes `window.ccBridge`, clears storage, tombstones and drafts, forgets the memoised `api/integrations` answer (`resetCodeGit`), restores `window.top`, resets the URL.
- `stubFetch.ts`: route table keyed `METHOD path` (or RegExp); an unstubbed request fails the test.
- `fakeEventSource.ts`: `emit`, `emitRaw`, `fail` (transient), `failClosed` (the browser gave up: `readyState` CLOSED), `reopen`; installed through `setEventSourceFactory`. `setup.ts` calls `resetSse()` after each test.
- `fakeBridge.ts`: `installBridge(session?)` with programmable `sendPrompt`/`openSession` and `emit`.
- `fakeTop.ts`: `installTop(location | 'unreadable')` makes the page look framed by cc (`window.top`); with `installBridge()` it enables the code-git links.
- `fixtures.ts`: wire-shaped builders. `renderCtx.tsx`: render under a `ReviewProvider` with spies.
- `fakeMedia.ts`: `installMedia({ [query]: matches })` stubs `matchMedia` for those queries (others fall through to happy-dom's 1024px window); `set(query, matches)` flips one and notifies.
- `fakeResizeObserver.ts`: `installResizeObserver()`; `resize(el | 'all', width)` delivers a width, `observed()` lists observed elements. Unstubbed, nothing is ever measured (width 0).
- happy-dom has no layout: geometry (drag across real rows, overflow, sticky headers) is checked by the Playwright harness.
- RTL's `waitFor` hangs under vitest fake timers; use `vi.waitFor` there.
