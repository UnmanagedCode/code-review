# Inbox gotchas

- **The inbox is store-only plus cc's metadata; it never calls `summaryOf`.** A summary costs 1–2 exec calls per review, and the inbox lists every open review of every project. So `listInbox` (`src/inbox.js`) reads the review files and asks cc only each project's location (`GET /api/projects/:name/location`) and the worktree list of each project with an open worktree review, through one lookup scope, `ROW_CONCURRENCY` at a time, and never the full project list; `tests/inbox.test.js` pins zero exec calls and those hits. Consequences: "checkout gone" means only "cc no longer knows it" (a directory deleted behind cc's back is not seen; a checkout cc deleted within the lookup TTL still shows), and a System that is down is never marked. Opening the review shows both.
- **A failed cc lookup is `checkoutGone: null`, never a refusal.** The inbox still answers; `ccFetch` already logged the `CONDUCTOR_UNAVAILABLE`. `true` wins over `null`: a row whose project cc answers `PROJECT_UNKNOWN` for is gone even if its worktree lookup failed.
- **`agentSeq` exists because refreshes record no actor.** A round has no author, so "the agent refreshed into a new round" could not be told from a human refresh. `refreshReview(id, actor)` takes the actor; the REST route passes `HUMAN`, `refresh_review` the MCP caller. Only an agent refresh that adds a round sets `agentSeq`; an unchanged one writes nothing.
- **Turn compares against the newest submission's `seq`, not its time** (`turnOf` in `src/rollup.js`). A submission's `seq` is `review.seq` at compose time, so `agentSeq <= last.seq` means no agent activity since it was composed. Compose supersedes older pending/failed submissions, so the last array element is the live one; a pending or failed newest submission is always "your turn" (it needs Re-send or Mark as sent). Human activity while waiting never flips the turn back.
- **A refresh that adds a round bumps `seq`.** That gives the agent refresh a `seq` to record. It is safe for the other `seq` readers: unread counts compare message `seq`s, `NOTHING_TO_SUBMIT` compares `humanSeq`, and `markRead` reads up to `review.seq`.
- **`lastActivityAt` is the one wall-clock value logic reads,** and only to order reviews against each other (nothing orders one review's `seq` against another's). `touch` stamps it; `bump` calls `touch`, so every new `seq` is activity, and `composeSubmission`/`recordResult` call `touch` themselves. Non-activity writes (`markRead`, `PATCH`, the uncommitted sweep) must not call either.
- **An unmigrated open review is dropped from the inbox, never defaulted** (`migrated` in `src/inbox.js`). `migrateStore` logs and skips any per-review failure, and a file can be copied into `reviews/` while the server runs, so a readable review can lack `lastActivityAt`/`agentSeq`; without the guard the sort throws and `GET /inbox` answers 500. It is logged through `logSkipped`, like `store.list()`'s bad files.
- **The migration cannot recover agent refreshes stored before `agentSeq` existed** (`src/migrate.js`): it backfills `agentSeq` from agent messages only, so such a review may show "Waiting on agent" until the next agent activity.
