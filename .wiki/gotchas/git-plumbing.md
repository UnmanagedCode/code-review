# Git plumbing gotchas

- **Everything runs through cc's `POST /api/exec`**, local checkouts included (`src/exec.js`): no `execFile`, no `fs` on a checkout. Always `cwd: "/"` (a vanished checkout is then git's own answer, never an ambiguous `EXEC_SPAWN_FAILED`), always argv form (no quoting, no login profile), always `encoding: "base64"` (the only way to get bytes back exactly; decoding the Buffer as UTF-8 reproduces what `execFile`'s utf8 and `readFileSync(…,'utf8')` gave, invalid bytes included). Paths travel as `sh -c SCRIPT sh <path> …` arguments, never interpolated.
- **`git diff <commit>` rewrites `.git/index`** (stat refresh) even with `GIT_OPTIONAL_LOCKS=0` or `--no-optional-locks`; `git status` and `ls-files` do not. Uncommitted diffs run with `GIT_INDEX_FILE` pointing at a private temp copy (`withPrivateIndex` in `src/git.js`), made **on the target** (`<TMPDIR>/cr-index-*`) by the `CREATE_INDEX` script. The script runs after `cd` into the checkout, so it checks the base **before** `mktemp`: a relative `TMPDIR` would otherwise land inside the checkout, and one inside the checkout or the common git dir would write the tree or `.git`; all are `TEMP_UNUSABLE`, as is a base with `\n`/`\r` (rejected before `mktemp`). The JS-side check of the printed dir (`isTempDir`) is structural, not a regex: a `.` without the `s` flag misses line terminators, which once turned a created dir into a leak and a 500. In a linked worktree the index lives under the common git dir's `worktrees/<name>/`, so its path always comes from `rev-parse --git-path index`, never from `<checkout>/.git/index`. The copy takes the original's times exactly (`touch -r`): a copy that looks newer than its entries defeats git's racy-timestamp check, and a same-size edit made within one filesystem tick is then missed. (cc's exec has no utimes primitive, so `touch -r` inside the script is the way.) A missing index is not copied (git starts empty). `tests/snapshot.test.js` asserts byte-identical indexes for main and linked checkouts, `tests/remote.test.js` the whole `.git` over exec.
- **`core.splitIndex=true`:** the private copy links to the real `sharedindex.<sha>`, so writing it would write a new shared index into the real git dir; every call passes `-c core.splitIndex=false` (git still reads the split index, and writes the copy whole). **Git itself still bumps the existing `sharedindex.*`'s mtime on every read of a split index** (freshen-on-read, as a plain `git status` does; no config disables it), so that one mtime is the only `.git` stat a read changes; the split-index byte-identity tests allow only that field.
- **The alternates write is a second exec call** because its C-quoted entry is built in JS (`cQuote`) from the objects path the first call printed. Teardown (`removeTemp`) refuses any path whose basename is not `cr-index-*`; a failed teardown after success is a warning, not an error.
- **Diff flags are pinned** (`DIFF_FLAGS`): user config for external diff, textconv, prefixes or relative paths would otherwise change the parsed shape.
- **`git diff --no-index` exits 1 when files differ**; `DIFF_UNTRACKED` (run by `diffUntrackedBatch`) treats 0 and 1 as success.
- **Paths can be C-quoted** (`"a\tb"`, octal-escaped UTF-8) in `diff --git`, `---`/`+++` and `rename` lines; `unquote` in `src/diff.js` decodes them. A binary file has no `---`/`+++`, so its path comes from the `diff --git` line.
- **A branch `base` is stored as given and re-resolved through `merge-base <base> HEAD` every round** (`...` semantics). After `sync_worktree` moves the base forward, the range still shows only the checkout's own work. A sha base stays fixed.
- **The empty tree** (root commits, unborn HEAD) comes from `hash-object -t tree --stdin`, so it is correct for the repo's hash format.
- **Refs are untrusted input:** `checkRef` rejects anything outside `REF_RE` or starting with `-`; resolution uses `--end-of-options`.
- **Worktrees share the object store**, so range/commit reviews of a deleted worktree stay readable via the main checkout; only a garbage-collected sha gives `SNAPSHOT_GONE`.
- **fsmonitor:** every git call passes `-c core.fsmonitor=false`; with `core.fsmonitor=true` a plain `git status` spawns a detached daemon and writes `.git/fsmonitor--daemon*`. `tests/snapshot.test.js` compares the `.git` tree before and after. Not neutralised: a clean/smudge filter named by the reviewed repo's `.gitattributes` (git-lfs) still runs on working-tree paths, since a correct diff needs it.
- **`git rm --cached` paths** are in HEAD, absent from the index and present on disk: `diff HEAD` says deleted and `ls-files --others` says untracked. `readUncommitted` (`src/snapshot.js`) stages those paths into the private index and re-diffs, so the path appears once. `update-index --add` writes the blob, so the private index comes with a private `GIT_OBJECT_DIRECTORY` (real objects named in its `info/alternates` file); otherwise a recoverable copy of content the user deliberately untracked lands in the real `.git/objects`. **Never use `GIT_ALTERNATE_OBJECT_DIRECTORIES` for that:** it is colon-separated, so a checkout path containing `:` is split into bogus entries and every uncommitted review there fails; the alternates file takes one path per line, but a newline in the path would split it and a leading `#` comments it out, so `cQuote` in `src/git.js` always writes the entry C-quoted (control, `"`, `\` and non-ASCII bytes escaped; git unquotes entries starting with `"`). Restaged paths obey the size cap and are staged in one `update-index` batch; if the batch fails (a required clean filter, an unreadable file) they are staged one by one and unreadable ones become `tooLarge`; vanished ones stay deleted.
