# Testing and harnesses

- `npm test` = `typecheck` + `node --test tests/*.test.js` + `vitest run` (happy-dom). The node glob is quoted in `package.json` so npm's shell does not expand it differently across platforms.
- Backend tests start `start({ port: 0, distDir })` against a temp dist; never rely on a real `frontend/dist` or a fixed port.
- **The mutation harness judges the backend: `server.js` and `src/`** (`runner: node-test`, one runner per harness). UI tests run under vitest and are outside it.
- Git tests build repos under `os.tmpdir()` (`tests/_git.js`), never inside the project tree; the fake cc (`tests/_fakeCc.js`) is wired by setting `CONDUCTOR_URL`; the store by `CODE_REVIEW_STORE` (`tests/_store.js`). `tests/_*.js` helpers are not matched by the test glob.
- **Every git call needs a fake cc**, since git runs through its `POST /api/exec`: a test that calls `git.js`/`snapshot.js` directly starts one per file (`before`/`after`) and passes `localPlace(dir)`.
- **Remote systems are faked with a virtual root** (`/cr-remote-<hex>`, `world({system, remoteId})`): the fake rewrites argv/cwd/env under it to the real temp dir. The root must not exist on this machine, so a leftover host-local `fs` or `execFile` on a remote path fails instead of silently reading the real dir. Count calls with `state.execCalls`, inject refusals with `state.execHook`, pin `TMPDIR` with `state.execEnv`.
- **The fake cc's `displayLabel` is a stand-in** (`title || firstPrompt || <id prefix>…`), not cc's rule: a test that asserts a label sets `displayLabel` on its row. `state.displayLabel = false` sends rows without the field (a cc that lacks it). `world().session()` takes `title` and `firstPrompt` to seed an untitled session.
- **The fake cc can fail on demand:** `state.hits`, `state.resetNext`, `state.delayMs` (per route when a function), `state.getHook`, and `execHook` returning `'reset'` (see its JSDoc); `state.execDelayMs` with `state.execMaxInFlight` measure concurrency. It sets `CODE_REVIEW_CC_RETRY_MS=1` (retries are instant), `CODE_REVIEW_LOOKUP_TTL_MS=0` and a temp `CODE_REVIEW_STORE` when none is set, so no test logs into a real store.
- **The lookup cache outlives a test.** It is module state keyed by project name, and the fixtures all call their project `app`. With the fake's TTL 0 no answer is reused; a test that raises the TTL must `_clearLookups()` first (entries recorded at TTL 0 are fresh once it rises). It ages on `performance.now()`, so `t.mock.timers` on `Date` cannot revive an entry.
- **Fixture shas repeat across tests** (pinned identity and dates), so process-wide caches keyed by sha (committed snapshots, line counts) can already hold a test's answers; an exec-count test seeds a unique commit (`uniqueBase` in `tests/diffMeta.test.js`) or warms the cache itself. The filesystem guard in `tests/exec.test.js` allows `store.js` and `opsLog.js`.
- `harness/bench/open-review.mjs` times `openReview`, `harness/bench/requests.mjs` every review-page request (cc GETs, execs, ms, cold and warm), for any checkout's `src/` (`--tree`) against this tree's fake cc; not tests.
- **`execHook` runs before the command** and must not throw (an exception inside the fake leaves the request unanswered until the exec timeout). To act between two calls (a file vanishing after the untracked listing), act on the next call's hook.
- `harness/bench/highlight.mjs` imports `frontend/src/lib/highlight/index.ts` through Node's type stripping (like `tests/links.test.js` with `route.ts`): `index.ts` must keep only type imports from `prism.ts`. It runs each language in a child process; timings in one long process are inflated by GC.
- Each temp repo sits in its own `mkdtemp` dir (`tests/_git.js`) that also holds its worktrees and fixtures; cleanup removes exactly that path, never a name pattern.
- Real cc and the real `$PROJECTS_ROOT/.code-review` are never touched by tests.
- `harness/playwright/snap.mjs` and `golden.mjs` write screenshots to `harness/playwright/out/` (gitignored). They tolerate exactly the two host-URL 404s, plus 502s during `snap.mjs`'s system-down step (`seed().systemDown(true)` makes the fake cc refuse every exec).
- Mutation `baseline` needs a clean tree and `CC_PROJECTS_ROOT` exported.
- UI tests: vitest + happy-dom with shared fakes in `frontend/src/test/` (fetch route table, EventSource, `ccBridge`, fixtures); see [ui.md](ui.md).
- **Scope harness waits to the pane you shot.** The diff's inline thread cards are `article`s too, so a bare `getByRole('article')` resolves before the Threads tab's list has loaded; `snap.mjs` waits inside the `tabpanel`.
- `harness/playwright/seed.mjs` seeds one world through the REST/MCP API using `tests/_world.js`; `snap.mjs` and `golden.mjs` use it. Run `npm run prepare` first so `frontend/dist` is current. Its `syntax` worktree (the highlighting review) is a second worktree of `app`, so the checkout selects list it.
- **`tests/links.test.js` imports `frontend/src/lib/route.ts` under Node type stripping**, so `route.ts` must stay erasable-only TypeScript, import nothing but `react` (no `@/` aliases), and touch DOM globals only inside functions.
- **UI tests share a module-level resource cache and SSE stream.** `frontend/src/test/setup.ts` calls `resetResources()` and `resetSse()` after each test; inside one test, a second mount of the same key reads the cache, so call `resetResources()` between mounts that must fetch. Tests that touch polling or freshness fake `Date` along with the timers (`toFake` including `'Date'`) and advance past `REFOCUS_MIN_MS` between focus events.
- `frontend/src/App.requests.test.tsx` is the request budget: it drives `App` through list → review → files → list → review with per-step fetch and `EventSource` counts and asserts them. `harness/playwright/requests.mjs` measures the same session in a real browser against the seeded world.
