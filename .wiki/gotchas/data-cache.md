# Client data layer gotchas

- **The event stream is never closed by unsubscribing.** `App` swaps `ListPane` for `ReviewView`, and React runs every passive unmount before the mounts, so a stream released with its last subscriber closed and reopened on each list ↔ review move. `frontend/src/lib/sse.ts` opens it once per page load. The host contract (cc's `docs/plugin-ui.md`) is the same: create long-lived resources once per page load, never release them because the page was hidden.
- **CLOSED is not reconnecting.** The browser retries an `EventSource` that hit a network error, but gives up for good (`readyState` CLOSED) on a non-2xx answer such as 503 `STORE_UNCONFIGURED` or a 502 while the plugin backend restarts. With a permanent stream nothing else would reopen it, so `openSource` (`frontend/src/lib/sseSource.ts`) retries with a doubling delay and treats the next `open` as a reconnect (events may have been missed).
- **`version` is global per key, not per mount.** It is the review entry's load count and survives a revisit, so consumers that compare it to a remembered value (`lastVersion` refs, read marks) see the cached number on remount and do not refetch. Read marks are still forgotten per visit (`forgetMarks`). Never reset it.
- **Age is checked only on mount.** A visible entry that ages while mounted is never refetched for that; events, `reload()` and polling are the only triggers. A hidden tab's stale entries wait for `visibilitychange`.
- **An event during an in-flight fetch must not be lost.** The fetch may predate the change, so `staleGen` (set by every invalidation) must be newer than the generation the fetch started at for it to clear `stale`; otherwise it runs again. `frontend/src/state/resource.ts` `load`.
- **The list's key tells `undefined` from `''`.** `worktree` undefined = every checkout, `''` = the main checkout; `resourceKey` alone would read both as `''`, so `useReviewList` encodes the scope (`*` vs `=<worktree>`).
- **The list ignores only its own echo:** an event for a listed row at or below the row's `rev`. An own write on a review leaves the list's row older, so it still refetches the list.
- **`focus` fires on every click into the plugin iframe from cc's shell**, and a return to a tab fires `focus` and `visibilitychange` together; `usePolling` gates both on `REFOCUS_MIN_MS` since the last kick or load.
- **The idle cache holds `MAX_IDLE_ENTRIES` (32) unmounted entries**, least recently used out: file diffs can be large.
- **Compare against the response's sig, not the sig the request was made under.** A diff fetched after a change already carries the new sig, so the next review load finds it current instead of fetching twice (`useFileDiff`).
- **A local `patchSig` runs ahead of the review's sig until the review reloads.** The sig comparison therefore runs once per (file, view sig), not on every cache change; otherwise the patched entry would read as stale and refetch at once.
- **An own write costs a diff refetch only when its `fileSig.sig` is null** (the path is not in the diff, or the snapshot is unreadable). The UI cannot know the file's new sig without the server; `patchSig` only accepts a non-null sig for the open path, because only the open file's entry holds the local patch. A review thread's write has `fileSig: null` (not `{sig: null}`): it touches no file, the files' sigs do not move, so the review reload refetches no diff.
- **`keepPrevious` needs the switching guard.** While the previous file stays on screen, `expand`, `reveal`, `ensureTexts`, the total effect and the baseline effect return early (`switching`), or they would read lines of the new path for the old file; the baseline effect also depends on `path`, since two files can want the identical baseline.
- **A delete must outlive the mount.** `deleted` is the review entry's `gone` flag, set from the event even while nobody has the review open, so a revisit shows the deleted state from the cache with no fetch (the cached detail would be writable and every action would 404). `frontend/src/state/review.ts`.
- **Kicks join a fetch already running.** The cache's visibility flush, an aged mount and the poll's focus/visibility kick all fire on one transition; `usePolling` reloads with `{ join: true }`, which does nothing while a fetch that started after the last invalidation runs. A plain `reload()` (an own write) and an event after the fetch started still refetch.
- **A bfcache restore missed events.** A persisted `pageshow` is a reconnect for the tab (lists and the inbox have no polling), in the worker and in-tab transports alike.
- **Entries created in render are not idle.** Only `ensure` counts a new entry as idle at once; a hook's entry joins the LRU when it unmounts, so mounting the review does not evict the diff entry beside it.
- **The SharedWorker resolves URLs against `assets/`, not the page.** Vite emits the worker as `assets/sseWorker-*.js`, so a relative `api/events` inside it would hit `assets/api/events`; the tab sends its absolute URL in `hello` (`frontend/src/lib/sseTransport.ts`). cc's CSP allows it: `worker-src` falls back to `script-src 'self'`.
- **A SharedWorker's requests are invisible to Playwright's page and context `request` events.** `harness/playwright/requests.mjs` counts `api/events` connections at a proxy in front of the server instead.
- **The worker needs no tab-side release.** Tabs send `bye` on `pagehide` and the hub closes the stream with the last one; a tab that crashes sends none, but the browser ends a SharedWorker when no document owns it, which ends its EventSource.
